# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Python 3.13+, dependencies managed with `uv`. Lint and format with ruff (configured in `pyproject.toml`, line length 100): `uv run ruff check .` and `uv run ruff format .`.

```bash
uv sync                                  # install dependencies
./run.sh                                 # start server (cd backend && uvicorn app:app --reload --port 8000)
cd backend && uv run uvicorn app:app --reload --port 8000   # equivalent manual start
uv run pytest                            # run unit tests (backend/tests; no network/LLM/model download)
uv run mypy backend                      # type check (config in pyproject.toml)
```

- Web UI: http://localhost:8000 · API docs: http://localhost:8000/docs
- Requires a `.env` file in the project root containing `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` and `JWT_SECRET` (the server refuses to start without it; `.env.example` is the template). `config.py` loads it with `load_dotenv()`. `GUARD_API_KEY` (OpenRouter) is optional and enables the input guard (see Architecture item 3). LangSmith tracing is optional (see Architecture item 12).
- On Windows, run commands from Git Bash (the README requires it; `run.sh` is a bash script).

## Things that break if you ignore them

- **Working directory matters.** The server must be started from `backend/`. Startup loads course documents from the relative path `../docs`, the static frontend is mounted from `../frontend`, and ChromaDB persists to `./chroma_db` (relative, so it lands in `backend/chroma_db/`). Running uvicorn from the root will silently skip the docs and the frontend.
- **Documents are deduplicated by course title, not by content.** `RAGSystem.add_course_folder` skips any file whose parsed title already exists in the `course_catalog` collection. Editing a course file and restarting will NOT re-index it. To rebuild, delete `backend/chroma_db/` or call `add_course_folder(..., clear_existing=True)`.
- **Course file format is parsed positionally.** `DocumentProcessor.process_course_document` expects line 1 `Course Title: ...`, line 2 `Course Link: ...`, line 3 `Course Instructor: ...`, then `Lesson N: Title` markers, optionally followed by a `Lesson Link: ...` line. Files without lesson markers fall back to a single unnumbered chunk stream.
- Supported extensions for folder ingestion: `.pdf`, `.docx`, `.txt`. Note that `DocumentProcessor.read_file` (which delegates to `utils/file_utils.read_text_file`) only reads text, so PDF/DOCX content will not be parsed correctly with the current code.
- **Log, don't print.** Modules use `logger = logging.getLogger(__name__)`; handlers are configured once by `setup_logging()` in `app.py`. Don't add `print()` or call `logging.basicConfig()`. Use `logger.exception(...)` inside `except` blocks so tracebacks are kept.
- The LLM provider is any OpenAI-compatible endpoint, set via `LLM_BASE_URL` / `LLM_MODEL` (defaults in `backend/config.py`: Groq). API limits (`max_tokens=1600`, `temperature=0`, `max_retries=3`) are the `ChatOpenAI(...)` arguments in `AIGenerator.__init__`.

## Architecture

The request flow spans several modules, so it helps to read them together:

1. **`backend/app.py`** — FastAPI app. `POST /api/query` requires a bearer token (`get_current_user`); it creates a user-owned session if the client doesn't send a `session_id`, returns 404 for a session the caller doesn't own, then calls `RAGSystem.query`. `/api/auth/*` is mounted from `auth.py` (item 8a). `GET /api/courses` returns catalog stats. Startup event ingests `../docs`. CORS and TrustedHost are wide open.
2. **`backend/rag_system.py`** — Orchestrator. Owns all components and wires them together. `query()` first runs the input guard (if enabled); a blocked message returns `InputGuard.BLOCKED_MESSAGE` with no sources, skips the LLM and is not saved to session history. Otherwise it builds a prompt, asks the AI generator for an answer with the tool definitions attached, then collects sources from the tool manager and records the exchange in session history.
3. **`backend/input_guard.py`** — Pre-LLM safety/scope check. `InputGuard.is_safe(query)` calls `respan/span-01-lite:free` through the OpenRouter **Decisions API** (`POST https://openrouter.ai/api/alpha/decisions`, alpha; NOT the chat-completions endpoint, so `ChatOpenAI`, tool calling and structured output do not work with it) via plain `httpx`. It sends three `noul` questions (`harmful`, `jailbreak`, `out_of_scope`) from `InputGuard.BEHAVIORS`; each answer is `answers.<id>.noul`, a P(true) float. The message is blocked if any score is `>= GUARD_THRESHOLD` (default 0.5). It **fails open**: HTTP errors, `refusal` answers or malformed responses log an exception and allow the query. Disabled when `GUARD_API_KEY` is empty. The `out_of_scope` wording names the current courses' topics; if you add courses on other subjects, update it, or valid questions get blocked (the first untuned wording blocked everything). The guard sees only the current message, not history.
4. **`backend/ai_generator.py`** — LLM calls via LangChain's `ChatOpenAI` (`langchain-openai`, Chat Completions path, not the Responses API) pointed at `LLM_BASE_URL` (Groq and Gemini both expose OpenAI-compatible chat completions). This is an agentic tool loop with a hard limit of **one tool round**: the first call uses `llm.bind_tools(tools)`; if the returned `AIMessage` has `tool_calls`, it executes them, appends each result as a `ToolMessage`, then makes a second call on the unbound `llm` (no tools) to produce the final text. The system prompt (a `SystemMessage`) enforces "one search per query" and that general-knowledge questions are answered without searching. Conversation history is sent as prior `HumanMessage`/`AIMessage` messages between the system prompt and the query. `openai.RateLimitError` still propagates from LangChain and is translated to `LLMRateLimitError`.
5. **`backend/search_tools.py`** — Tool abstraction. `Tool` is an ABC with `get_tool_definition()` (OpenAI function-tool schema: `{"type": "function", "function": {...}}`, which `bind_tools` accepts directly; `ToolManager.register_tool` reads the name from `function.name`) and `execute()`. `ToolManager` registers tools by name and dispatches calls. `CourseSearchTool` (the only tool, `search_course_content`) formats results as `[Course - Lesson N]` headers and stashes `last_sources` on the instance, which `ToolManager.get_last_sources()` later reads. Adding a tool means implementing the ABC and registering it in `RAGSystem.__init__`.
6. **`backend/vector_store.py`** — ChromaDB wrapper with two collections:
   - `course_catalog`: one document per course, keyed by course title (the ID). Metadata holds link, instructor, and a JSON blob of lessons. Used for **fuzzy course-name resolution**: a `course_name` filter is first resolved by vector-searching this collection, and the top hit's title becomes an exact `where` filter on `course_content`.
   - `course_content`: chunked lesson text with metadata `course_title`, `lesson_number`, `chunk_index`. Chunk IDs are `{title with spaces→_}_{chunk_index}`.
   Embeddings use `SentenceTransformerEmbeddingFunction` with `all-MiniLM-L6-v2`, which runs locally and downloads on first use.
7. **`backend/document_processor.py`** — Parses course files and chunks lesson text by sentences (target `CHUNK_SIZE`=800 chars with `CHUNK_OVERLAP`=100). The chunking algorithm itself lives in `utils/text_utils.chunk_text`; `DocumentProcessor.chunk_text` is a thin wrapper that passes the configured sizes. The first chunk of each lesson is prefixed with `Lesson N content:`; the last lesson's chunks are prefixed with the course title and lesson number. Chunk-prefix behavior is inconsistent across lesson branches, so check both before changing it.
8. **`backend/session_manager.py`** — In-memory dict of sessions, keyed `session_<random token>`, each owned by a user id (`create_session(user_id)`, `is_owner`). Keeps the last `MAX_HISTORY * 2` messages. Lost on restart. `/api/query` returns 404 for a session the caller doesn't own (unknown and foreign look identical).
8a. **Auth** — `backend/auth.py` (`create_auth(store, secret, expire_minutes)` returns the `/api/auth/{register,login,me}` router and the `get_current_user` dependency; in-memory per-IP `RateLimiter`), `backend/user_store.py` (sqlite3 `users` table at `USERS_DB_PATH`, default `backend/users.db`, email unique case-insensitively) and `backend/utils/security.py` (scrypt password hashing, HS256 JWT via PyJWT). `/api/query` requires `Authorization: Bearer <token>`; `/api/courses` stays public. In `app.py` the auth router must be included **before** the catch-all static mount. The frontend keeps the token in `localStorage` and shows a login/register modal when it is missing or rejected. Config: `JWT_SECRET`, `JWT_EXPIRE_MINUTES` (default 1440), `USERS_DB_PATH`.
8b. **Feedback** — each assistant answer shows thumbs up/down. `/api/query` returns a server-generated `message_id` (uuid, not persisted); the UI sends `POST /api/feedback` (`{message_id, rating: "up"|"down"|null, session_id}`, bearer token required, 204) and `null` clears the vote. `backend/feedback.py` is the router, `backend/feedback_store.py` the sqlite `feedback` table in the same file as users (`USERS_DB_PATH`), one row per (message_id, user_id). Only ratings are stored, not question/answer text.
8c. **Message history** — `/api/query` saves each exchange (question, answer, sources, `message_id`) to the sqlite `messages` table (`backend/message_store.py`, same `USERS_DB_PATH` file) after answering; a save failure is logged, not surfaced. `GET /api/messages` (`backend/messages.py`, bearer token required) returns the caller's last 200 messages oldest-first with their thumbs rating, and the frontend replays them under the welcome message after login (`showUser` → `loadHistory`). Only the display history is restored: the in-memory `SessionManager` is not, so the LLM does not see old messages after a restart/re-login (a new session starts). Unlike feedback, this stores question/answer text.
9. **`backend/config.py`** — Single `Config` dataclass instance, loads `.env` via `python-dotenv`. Tunables: chunk size/overlap, `MAX_RESULTS` (search top-k), `MAX_HISTORY` (exchanges remembered), `LOG_LEVEL` (default `INFO`) and `LOG_FILE` (optional rotating log file; console only when unset), and the guard settings `GUARD_API_KEY`, `GUARD_URL`, `GUARD_MODEL`, `GUARD_THRESHOLD`, and `LANGSMITH_CAPTURE_IO` (item 12).
10. **`frontend/`** — Plain HTML/JS/CSS with no build step. `script.js` calls `/api/query` and `/api/courses`, and keeps the `session_id` returned by the server to continue conversations.
11. **`backend/utils/`** — Shared helpers with no dependency on the domain modules. Import from the specific submodule:
   - `file_utils.py` — `read_text_file` (UTF-8 read, falls back to ignoring invalid bytes).
   - `text_utils.py` — `chunk_text(text, chunk_size, chunk_overlap)`, the sentence chunker.
   - `http_utils.py` — `parse_retry_after(headers)`, reads a numeric Retry-After header (HTTP-date values return None).
   - `logging_config.py` — `setup_logging(level, log_file)`. Replaces existing handlers on each call, and quiets chatty third-party loggers (httpx, openai, langchain, urllib3, huggingface_hub, …).
   Put new cross-module helpers here rather than in a domain module.

12. **LangSmith tracing** — Off unless `LANGSMITH_TRACING=true` (plus `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT`, optional `LANGSMITH_ENDPOINT`); LangChain/langsmith read these from the environment (`.env` is loaded by `config.py`). `RAGSystem.query` is the root run (`rag_query`); `InputGuard.is_safe` (`input_guard`, records scores), `CourseSearchTool.execute` (`search_course_content`) and `VectorStore.search` (`vector_store.search`, retriever run) are `@traceable` children, and the `ChatOpenAI` calls nest automatically. `app.py` passes `user_id` and `session_id` as run metadata via `langsmith_extra` (user id, never email). **Traces contain user questions and course text**; set `LANGSMITH_CAPTURE_IO=false` (read in `config.py`, maps to `LANGSMITH_HIDE_INPUTS/OUTPUTS`) to send only timing, structure and metadata. `backend/tests/conftest.py` forces tracing off so tests stay offline. Don't put secrets in traced function arguments or return values.

Data flow for a query: UI → `/api/query` (bearer token checked, session ownership verified) → `RAGSystem.query` → input guard (blocked → fixed refusal, flow ends) → LLM (may call `search_course_content`) → `VectorStore.search` (optional course-name resolution, then filtered Chroma query) → LLM writes the final answer → response includes `sources` from the tool.

## Dependencies of note

Pinned in `pyproject.toml`: `chromadb==1.0.15`, `openai==3.42.1` (still imported for its exception types), `langchain-openai` and `langchain-core` (resolved by `uv.lock`), `sentence-transformers==5.0.0`, `fastapi==0.116.1`, `langsmith` (tracing), `pyjwt` (JWT signing) and `email-validator` (pydantic `EmailStr`). `sentence-transformers` pulls in PyTorch, so the first `uv sync` is heavy.
