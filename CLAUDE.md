# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Python 3.13+, dependencies managed with `uv`. Lint and format with ruff (configured in `pyproject.toml`, line length 100): `uv run ruff check .` and `uv run ruff format .`.

```bash
uv sync                                  # install dependencies
./run.sh                                 # start server (cd backend && uvicorn app:app --reload --port 8000)
cd backend && uv run uvicorn app:app --reload --port 8000   # equivalent manual start
uv run pytest                            # run unit tests (backend/tests; no network/LLM/model download)
uv run mypy backend                      # type check (config in pyproject.toml)
cd backend && uv run python ingest.py    # one-off document ingestion (item 14)
docker compose up --build                # app + postgres + redis + ingest (items 13-14)
```

Tests run on sqlite and in-memory state by default. Set `TEST_DATABASE_URL=postgresql://...` to also run the store tests on PostgreSQL (CI does).

- Web UI: http://localhost:8000 · API docs: http://localhost:8000/docs
- Requires a `.env` file in the project root containing `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` and `JWT_SECRET` (at least 32 characters; the server refuses to start without it; `.env.example` is the template). `config.py` loads it with `load_dotenv()`. `GUARD_API_KEY` (OpenRouter) is optional and enables the input guard (see Architecture item 3). LangSmith tracing is optional (see Architecture item 12).
- On Windows, run commands from Git Bash (the README requires it; `run.sh` is a bash script).

## Things that break if you ignore them

- **Working directory matters.** The server must be started from `backend/`. By default startup loads course documents from the relative path `../docs` (`DOCS_PATH`), the static frontend is mounted from `../frontend` (`FRONTEND_PATH`), and ChromaDB persists to `./chroma_db` (`CHROMA_PATH`, so it lands in `backend/chroma_db/`). Running uvicorn from the root will silently skip the docs and the frontend. The Docker image sets absolute paths for all three.
- **Documents are deduplicated by course title, not by content.** `RAGSystem.add_course_folder` skips any file whose parsed title already exists in the `course_catalog` collection. Editing a course file and restarting will NOT re-index it. To rebuild, delete `backend/chroma_db/` or call `add_course_folder(..., clear_existing=True)`. Ingestion is atomic per course (`RAGSystem._ingest`): content is written first and the catalog entry last (the catalog entry is what marks a course as done); on failure the content is rolled back, and a file that yields no chunks is skipped. `VectorStore.get_existing_course_titles()` and `get_course_count()` raise on a Chroma read error instead of returning an empty list.
- **Course file format is parsed positionally.** `DocumentProcessor.process_course_document` expects line 1 `Course Title: ...`, line 2 `Course Link: ...`, line 3 `Course Instructor: ...`, then `Lesson N: Title` markers, optionally followed by a `Lesson Link: ...` line. Files without lesson markers fall back to a single unnumbered chunk stream.
- Supported extensions for folder ingestion: `.pdf`, `.docx`, `.txt`. `DocumentProcessor.read_file` delegates to `utils/file_utils.read_document` (pypdf for PDF, python-docx for DOCX, UTF-8 text otherwise); the extracted text must still follow the positional course format. Chunk text now always starts with `Course <title> Lesson N content: ` (no-lesson files: `Course <title> content: `), so existing `backend/chroma_db/` data indexed with the old prefixes is not rewritten until you delete it.
- **Log, don't print.** Modules use `logger = logging.getLogger(__name__)`; handlers are configured once by `setup_logging()` in `app.py`. Don't add `print()` or call `logging.basicConfig()`. Use `logger.exception(...)` inside `except` blocks so tracebacks are kept.
- The LLM provider is any OpenAI-compatible endpoint, set via `LLM_BASE_URL` / `LLM_MODEL` (defaults in `backend/config.py`: Groq). API limits (`LLM_MAX_TOKENS`=1600, `LLM_TEMPERATURE`=0, `LLM_MAX_RETRIES`=3, `LLM_TIMEOUT`=60 s per request) live in `config.py` and are passed through `RAGSystem` to `AIGenerator.__init__`, which hands them to `ChatOpenAI(...)`.
- **Put limits in `config.py`, not inline.** Numeric limits (lengths, rate limits, timeouts, cache ages) belong in `Config`; modules receive them as arguments or read `config`. Still hardcoded: scrypt parameters (`utils/security.py`), log rotation size (`logging_config.py`), and `feedback.py` field lengths.

## Architecture

The request flow spans several modules, so it helps to read them together:

1. **`backend/app.py`** — FastAPI app. `POST /api/query` is a plain `def` (runs in FastAPI's threadpool, because the whole RAG stack is blocking; shared state such as `SessionManager` and `RateLimiter` is lock-protected) and requires a bearer token (`get_current_user`); it creates a user-owned session if the client doesn't send a `session_id`, returns 404 for a session the caller doesn't own, then calls `RAGSystem.query`. `/api/auth/*` is mounted from `auth.py` (item 8a). `GET /api/courses` returns catalog stats. A `lifespan` handler purges old messages (`MESSAGE_RETENTION_DAYS`) and ingests `DOCS_PATH` on startup unless `INGEST_ON_STARTUP=false` (item 14), and closes the database pool on shutdown. CORS origins and trusted hosts come from `ALLOWED_ORIGINS` / `ALLOWED_HOSTS` (comma-separated, default `*`; credentials are never allowed cross-origin because auth uses bearer tokens). `BodySizeLimitMiddleware` (`utils/body_limit.py`) returns 413 for bodies over `MAX_BODY_BYTES` (64 KiB). `GET /healthz` is an unauthenticated liveness probe and `GET /readyz` the readiness probe (item 13). **Streaming:** `POST /api/query/stream` is an `async def` endpoint (the LLM is awaited on the event loop; tools and sqlite saves use worker threads; a client disconnect closes the generator and cancels the LLM call) and the same auth, rate limit and session checks, returning `text/event-stream` of JSON `data:` frames: `{type:"delta",text}` while the answer is written, then `{type:"done",answer,sources,session_id,message_id}`, or `{type:"error",detail,status}` if it fails after the first token. Failures before the first token (401/404/429/500) are plain HTTP errors because the endpoint pulls the first item before returning the response. The exchange is persisted when `done` is built. The security headers are a pure-ASGI middleware (`utils/security_headers.py`) so streamed bodies are not wrapped; `/api/query` is unchanged. Failed logins, rate-limit hits, rejected tokens and session-ownership failures are logged at WARNING (ids/IPs only, never passwords or question text). A middleware adds a strict CSP (not on `/docs`, `/redoc`), `X-Frame-Options`, `nosniff` and `Referrer-Policy`; 500s return a generic message with an error id (details only in the log).
2. **`backend/rag_system.py`** — Orchestrator. Owns all components and wires them together. `query()` first runs the input guard (if enabled); `query()` returns a `QueryResult(answer, sources, blocked)`; a blocked message returns `InputGuard.BLOCKED_MESSAGE` with no sources, skips the LLM and is not saved to session history or to the message store. Otherwise it builds a prompt, asks the AI generator for an answer with the tool definitions attached, then collects sources from the tool manager and records the exchange in session history.
3. **`backend/input_guard.py`** — Pre-LLM safety/scope check. `InputGuard.is_safe(query)` calls `respan/span-01-lite:free` through the OpenRouter **Decisions API** (`POST https://openrouter.ai/api/alpha/decisions`, alpha; NOT the chat-completions endpoint, so `ChatOpenAI`, tool calling and structured output do not work with it) via plain `httpx` (`is_safe` blocking for `/api/query`; `ais_safe` on a shared lazily-created `httpx.AsyncClient` for the streaming path, closed by `aclose()` in the app's `lifespan` shutdown). It sends three `noul` questions (`harmful`, `jailbreak`, `out_of_scope`) from `InputGuard.BEHAVIORS`; each answer is `answers.<id>.noul`, a P(true) float. The message is blocked if any score is `>= GUARD_THRESHOLD` (default 0.5). It **fails open**: HTTP errors, `refusal` answers or malformed responses log an exception and allow the query. Disabled when `GUARD_API_KEY` is empty. The `out_of_scope` wording names the current courses' topics; if you add courses on other subjects, update it, or valid questions get blocked (the first untuned wording blocked everything). The guard receives the last few turns of the session as context (`is_safe(query, history)`) so follow-ups like "and lesson 3?" are not judged alone.
4. **`backend/ai_generator.py`** — LLM calls via LangChain's `ChatOpenAI` (`langchain-openai`, Chat Completions path, not the Responses API) pointed at `LLM_BASE_URL` (Groq and Gemini both expose OpenAI-compatible chat completions). This is an agentic tool loop with a hard limit of **one tool round**: the first call uses `llm.bind_tools(tools)`; if the returned `AIMessage` has `tool_calls`, it executes them, appends each result as a `ToolMessage`, then makes a second call on the unbound `llm` (no tools) to produce the final text. A tool that raises (bad arguments, backend error) does not fail the request: the error text goes back to the model as the `ToolMessage`. The system prompt (a `SystemMessage`) enforces "one search per query" and that general-knowledge questions are answered without searching. Conversation history is sent as prior `HumanMessage`/`AIMessage` messages between the system prompt and the query. If the provider stops at `max_tokens` (`finish_reason=length`) a visible "cut off" notice is appended to the answer. `openai.RateLimitError` still propagates from LangChain and is translated to `LLMRateLimitError`. `astream_response` is the natively async streaming twin (same one-tool-round limit, `llm.astream` on the existing client, yields text deltas, truncation notice last; the blocking tool run goes through `asyncio.to_thread`); `RAGSystem.aquery_stream` (async generator; awaits `ais_safe`) yields `str` deltas then a final `QueryResult`, saving session history only once the answer is complete.
5. **`backend/search_tools.py`** — Tool abstraction. `Tool` is an ABC with `get_tool_definition()` (OpenAI function-tool schema: `{"type": "function", "function": {...}}`, which `bind_tools` accepts directly; `ToolManager.register_tool` reads the name from `function.name`) and `execute()`. `ToolManager` registers tools by name and dispatches calls. `CourseSearchTool` (the only tool, `search_course_content`) formats results as `[Course - Lesson N]` headers and returns the sources with the text (`ToolResult.sources`, each a `models.Source(label, url)`, deduplicated; the url is the lesson link, else the course link, from `VectorStore.get_lesson_link`/`get_course_link`); `AIGenerator` appends them to a per-request `sources_out` list. The API returns `sources` as `[{label, url}]`; messages saved before links existed (plain strings) are upgraded on read, and the frontend only renders http(s) urls as links. (Previously these were stashed on the instance, which is returned in a `ToolResult(text, sources)`; there is no per-request state on the shared tool. Adding a tool means implementing the ABC and registering it in `RAGSystem.__init__`.
6. **`backend/vector_store.py`** — ChromaDB wrapper with two collections:
   - `course_catalog`: one document per course, keyed by course title (the ID). Metadata holds link, instructor, and a JSON blob of lessons. Used for **fuzzy course-name resolution**: a `course_name` filter is first resolved by vector-searching this collection, and the top hit's title becomes an exact `where` filter on `course_content`. A hit farther than `COURSE_MATCH_MAX_DISTANCE` (L2, default 1.6) counts as "no such course".
   - `course_content`: chunked lesson text with metadata `course_title`, `lesson_number`, `chunk_index`. Chunk IDs are `{sha256(title)[:16]}_{chunk_index}`, so titles like "A B" and "A_B" cannot collide (data indexed before this change keeps the old `{title with spaces→_}_{chunk_index}` ids).
   Embeddings use `SentenceTransformerEmbeddingFunction` with `all-MiniLM-L6-v2`, which runs locally and downloads on first use.
7. **`backend/document_processor.py`** — Parses course files and chunks lesson text by sentences (target `CHUNK_SIZE`=800 chars with `CHUNK_OVERLAP`=100). The chunking algorithm itself lives in `utils/text_utils.chunk_text`; `DocumentProcessor.chunk_text` is a thin wrapper that passes the configured sizes. The first chunk of each lesson is prefixed with `Lesson N content:`; the last lesson's chunks are prefixed with the course title and lesson number. Lesson finalization lives in one helper (`finish_lesson`), so all chunks share one prefix scheme.
8. **`backend/session_manager.py`** — In-memory dict of sessions, keyed `session_<random token>`, each owned by a user id (`create_session(user_id)`, `is_owner`). Keeps the last `MAX_HISTORY * 2` messages. Lost on restart, unless `REDIS_URL` is set: `RedisSessionManager` (item 14) then keeps sessions in Redis with the same interface. Idle sessions expire after `SESSION_TTL_SECONDS` (24 h) and at most `MAX_SESSIONS` (10000) are kept (least recently used evicted); `RateLimiter` forgets idle keys. `/api/query` returns 404 for a session the caller doesn't own (unknown and foreign look identical).
8a. **Auth** — `backend/auth.py` (`create_auth(store, secret, expire_minutes)` returns the `/api/auth/{register,login,me}` router and the `get_current_user` dependency; in-memory per-IP `RateLimiter`), `backend/user_store.py` (`users` table in sqlite at `USERS_DB_PATH`, default `backend/users.db`, or PostgreSQL when `DATABASE_URL` is set; email unique case-insensitively) and `backend/utils/security.py` (scrypt password hashing, HS256 JWT via PyJWT). `/api/query` requires `Authorization: Bearer <token>`; `/api/courses` stays public. In `app.py` the auth router must be included **before** the catch-all static mount. The frontend keeps the token in `localStorage` and shows a login/register modal when it is missing or rejected. Config: `JWT_SECRET`, `JWT_EXPIRE_MINUTES` (default 1440), `USERS_DB_PATH`, `PASSWORD_MIN_LENGTH`/`PASSWORD_MAX_LENGTH` (8/128), and the login/register per-IP limiter `AUTH_RATE_LIMIT`/`AUTH_RATE_WINDOW` (10 per 60 s, passed to `create_auth` from `app.py`). `/api/query` is also rate limited per user (the `limit_queries` dependency in `app.py`, reusing `RateLimiter`; `QUERY_RATE_LIMIT` default 20 per `QUERY_RATE_WINDOW` default 60 s) and returns 429 with `Retry-After`. The limiter is in-memory and per-process unless `REDIS_URL` is set, which switches it to a shared Redis limiter (item 14). `limit_queries` also enforces `DAILY_QUERY_QUOTA` (item 13).
8b. **Feedback** — each assistant answer shows thumbs up/down. `/api/query` returns a server-generated `message_id` (uuid, not persisted); the UI sends `POST /api/feedback` (`{message_id, rating: "up"|"down"|null, session_id}`, bearer token required, 204) and `null` clears the vote. `backend/feedback.py` is the router, `backend/feedback_store.py` the `feedback` table in the same database as users (sqlite file `USERS_DB_PATH`, or PostgreSQL), one row per (message_id, user_id). Only ratings are stored, not question/answer text.
8c. **Message history** — `/api/query` saves each exchange (question, answer, sources, `message_id`) to the `messages` table (`backend/message_store.py`, same database as users) after answering; a save failure is logged, not surfaced. `GET /api/messages` (`backend/messages.py`, bearer token required) returns the caller's last `MAX_STORED_MESSAGES` (200) messages oldest-first with their thumbs rating; the optional `session_id` query param limits it to one session. The frontend replays the current session's messages under the welcome message (`showUser` → `loadHistory`) after a refresh or logout/login, until the user clears the conversation. Only the display history is restored: with the default in-memory `SessionManager` it is not, so after a server restart the old messages still show but the next question gets a 404 and starts a new session (with `REDIS_URL` the session survives restarts until its TTL). Unlike feedback, this stores question/answer text. `backend/tests/test_app_endpoints.py` exercises the HTTP layer with a mocked `RAGSystem` (imports `app` fresh against a temp database).
9. **`backend/config.py`** — Single `Config` dataclass instance, loads `.env` via `python-dotenv`. Tunables: chunk size/overlap, `MAX_RESULTS` (search top-k), `MAX_HISTORY` (exchanges remembered), `LOG_LEVEL` (default `INFO`) and `LOG_FILE` (optional rotating log file; console only when unset), the LLM limits (`LLM_MAX_TOKENS`, `LLM_TEMPERATURE`, `LLM_MAX_RETRIES`), the guard settings `GUARD_API_KEY`, `GUARD_URL`, `GUARD_MODEL`, `GUARD_THRESHOLD`, `GUARD_TIMEOUT`, the cache ages `CONFIG_CACHE_SECONDS` (3600, `/api/config`) and `COURSES_CACHE_SECONDS` (60, `/api/courses`), `LANGSMITH_CAPTURE_IO` (item 12), and the production settings in items 13-14 (`DATABASE_URL`, `REDIS_URL`, `INGEST_ON_STARTUP`, `DAILY_QUERY_QUOTA`, `MAX_HISTORY_CHARS`, `MESSAGE_RETENTION_DAYS`, `ENABLE_API_DOCS`, `ENABLE_HSTS`, `CHROMA_PATH`, `DOCS_PATH`, `FRONTEND_PATH`).
10. **`frontend/`** — Plain HTML/JS/CSS with no build step. `marked` and `DOMPurify` are vendored in `frontend/vendor/` (no CDN); assistant markdown goes through `renderMarkdown` (marked, then DOMPurify) before `innerHTML`. `script.js` calls `/api/query` and `/api/courses`, and keeps the `session_id` returned by the server to continue conversations. The id and its owning user id live in `sessionStorage` (per tab), so refresh and logout/login resume the same session for the same user; another user logging in drops it. `sendMessage` reads the SSE stream with `fetch` + `getReader` (`readEventStream`; `EventSource` can't send the bearer token), re-rendering the markdown as text arrives and swapping in the final message (sources, feedback) on `done`. The sidebar "Clear conversation" button (`createNewSession`) clears the chat and the stored session.
11. **`backend/utils/`** — Shared helpers with no dependency on the domain modules. Import from the specific submodule:
   - `file_utils.py` — `read_text_file` (UTF-8 read, falls back to ignoring invalid bytes).
   - `text_utils.py` — `chunk_text(text, chunk_size, chunk_overlap)`, the sentence chunker.
   - `http_utils.py` — `parse_retry_after(headers)`, reads a numeric Retry-After header (HTTP-date values return None).
   - `db.py` — the `Database` abstraction over sqlite/PostgreSQL (item 14) and `connect(path)`, the sqlite helper (WAL + 10 s busy timeout); the `feedback` table schema lives only in `feedback_store.feedback_schema`. `redis_client.py` — `get_redis(url)`, one cached client per URL.
   - `body_limit.py` — `BodySizeLimitMiddleware` (413 over the byte cap).
   - `logging_config.py` — `setup_logging(level, log_file)`. Replaces existing handlers on each call, and quiets chatty third-party loggers (httpx, openai, langchain, urllib3, huggingface_hub, …).
   Put new cross-module helpers here rather than in a domain module.

12. **LangSmith tracing** — Off unless `LANGSMITH_TRACING=true` (plus `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT`, optional `LANGSMITH_ENDPOINT`); LangChain/langsmith read these from the environment (`.env` is loaded by `config.py`). `RAGSystem.query` is the root run (`rag_query`); `InputGuard.is_safe` (`input_guard`, records scores), `CourseSearchTool.execute` (`search_course_content`) and `VectorStore.search` (`vector_store.search`, retriever run) are `@traceable` children, and the `ChatOpenAI` calls nest automatically. `app.py` passes `user_id` and `session_id` as run metadata via `langsmith_extra` (user id, never email). **Traces contain user questions and course text**; set `LANGSMITH_CAPTURE_IO=false` (read in `config.py`, maps to `LANGSMITH_HIDE_INPUTS/OUTPUTS`) to send only timing, structure and metadata. `backend/tests/conftest.py` forces tracing off so tests stay offline. Don't put secrets in traced function arguments or return values.

13. **Production hardening (Phase 0)** — `Dockerfile` / `docker-compose.yml` (state on the `/data` volume: `CHROMA_PATH`, `USERS_DB_PATH`, `HF_HOME`; uvicorn runs with `--proxy-headers`, trusting `X-Forwarded-For` only from `FORWARDED_ALLOW_IPS`) and `.github/workflows/ci.yml` (ruff, format check, mypy, pytest). `GET /readyz` returns 503 unless Chroma and the database (and Redis, when configured) all respond (`/healthz` stays liveness-only; the LLM/guard are not probed). `DOCS_PATH`, `FRONTEND_PATH` and `CHROMA_PATH` are env-configurable. `ENABLE_API_DOCS=false` removes `/docs`, `/redoc`, `/openapi.json`; `ENABLE_HSTS=true` adds Strict-Transport-Security (HTTPS only); startup warns when `ALLOWED_HOSTS`/`ALLOWED_ORIGINS` are `*`. `DAILY_QUERY_QUOTA` (500/user per rolling 24 h) is counted from the `messages` table in `limit_queries` (429 + `Retry-After: 3600`); blocked questions are not stored, so they don't count. `MAX_HISTORY_CHARS` (6000) caps the history sent to the LLM in `SessionManager.get_conversation_history` (oldest dropped first, never starts with an answer). `MESSAGE_RETENTION_DAYS` (0 = keep) purges old messages at startup. Schema changes after the baseline `CREATE TABLE IF NOT EXISTS` go in `utils/migrations.MIGRATIONS` (tracked with `PRAGMA user_version`, applied by `migrate()` in `app.py`; never edit a shipped entry). The Docker image is untested against a full build: on Linux `sentence-transformers` pulls the CUDA build of torch (multi-GB); pin the CPU wheel index if image size matters.

14. **Shared state (Phase 1)** — every piece of per-process state can move out of the process, each switched by one env var (empty = the old single-process behaviour, so dev and tests need nothing running). `DATABASE_URL` (postgres) points users/feedback/messages at PostgreSQL instead of the sqlite file: `utils/db.py` has `Database` (`SqliteDatabase`, `PostgresDatabase` with a `psycopg_pool` pool), stores take a `Database` (or a sqlite path) and write `?` placeholders; use `db.pk_column()`, `db.timestamp_column()`, `db.seconds_ago_sql()` and `db.integrity_errors` for the spots where dialects differ, and `db.run_ddl(...)` (advisory-locked on Postgres) for schema creation. Emails are looked up with `lower(email) = lower(?)` (unique `lower(email)` index on Postgres). `migrate(database)` tracks versions in `PRAGMA user_version` (sqlite) or a `schema_version` table (Postgres) and writes migrations in SQL valid on both. `REDIS_URL` switches `RAGSystem.session_manager` to `RedisSessionManager` (owner key + capped JSON list per session, TTL = `SESSION_TTL_SECONDS`; `MAX_SESSIONS` is not enforced) and `app.make_limiter` to `RedisRateLimiter` (fixed window, fails open and logs if Redis is down); the streaming path calls session methods via `asyncio.to_thread`. `/readyz` also pings Redis when configured. `INGEST_ON_STARTUP=false` skips startup ingestion; `cd backend && uv run python ingest.py [--clear] [--path DIR]` indexes the docs as a one-off job. `docker-compose.yml` wires postgres, redis, a one-shot `ingest` service and the app. The vector store is still embedded Chroma, so run a single app process/container until Phase 2. Tests: `backend/tests/test_phase1.py` runs store tests on sqlite always and on Postgres when `TEST_DATABASE_URL` is set (CI sets it); Redis code is tested with `fakeredis`.

Data flow for a query: UI → `/api/query` (bearer token checked, session ownership verified) → `RAGSystem.query` → input guard (blocked → fixed refusal, flow ends) → LLM (may call `search_course_content`) → `VectorStore.search` (optional course-name resolution, then filtered Chroma query) → LLM writes the final answer → response includes `sources` from the tool.

## Dependencies of note

Declared in `pyproject.toml` (most as `>=` minimums; `uv.lock` has the exact versions; only `openai` is pinned `==`): `chromadb`, `openai` (still imported for its exception types), `langchain-openai` and `langchain-core` (resolved by `uv.lock`), `sentence-transformers`, `fastapi`, `langsmith` (tracing), `pypdf` and `python-docx` (document reading), `httpx`, `pyjwt` (JWT signing) and `email-validator` (pydantic `EmailStr`). `sentence-transformers` pulls in PyTorch, so the first `uv sync` is heavy.
